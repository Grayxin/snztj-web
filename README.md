# 圣女之条件 · Mystic Arts 网页重制

基于本地安装版资源制作的浏览器动作游戏。项目提取了原版图像、地图和 MIDI 音乐，以 HTML、CSS 和原生 JavaScript 重建游戏运行逻辑，方便直接在浏览器中体验。

**当前状态：可玩的本地重建版。** 已按原 EXE 的静态关卡配置接入 16 个单屏场景、对应敌人及关键强敌，支持移动与二段跳、近战与魔法、敌人蓄力攻击和远程弹幕。场景顺序、敌人名单和清场推进有静态证据；HP、AI 时序和攻击判定仍为重建实现，不代表原作逐帧复刻。

## 快速开始

### 方式一：直接打开，适合立即游玩

1. 进入 `web` 目录。
2. 双击 `index.html`，或双击 `启动网页版.cmd`。
3. 等待图片读取完成，选择起始关卡后点击“开始冒险”。默认从第一场开始，也可以直接练习第 6、11、15、16 场强敌。

`启动网页版.cmd` 只是用 Windows 默认浏览器打开同目录的 `index.html`，不会安装软件，也不会启动后台服务。

直接游玩不需要 Python、Node.js、REA，也不需要运行安装或构建命令。请保留整个 `web` 目录，不能只复制 `index.html`；页面还需要同目录脚本和 `assets` 下的资源。

### 方式二：本地 HTTP 服务，适合开发和调试

如果电脑已经安装 Python 3，可在 PowerShell 中执行：

```powershell
cd 'D:\BaiduNetdiskDownload\圣女之条件\web'
python -m http.server 8765 --bind 127.0.0.1
```

然后打开 [本地游戏页面](http://127.0.0.1:8765/)。请保持终端运行；结束后，在终端按 `Ctrl+C` 停止服务。

如果 `python` 命令不可用，但已安装 Windows Python Launcher，可以尝试：

```powershell
py -3 -m http.server 8765 --bind 127.0.0.1
```

端口被占用时，可改用 `8766`，浏览器地址也相应改为 `http://127.0.0.1:8766/`。

此服务绑定在本机回环地址，供当前电脑访问。项目目前没有在线账户、后端接口或多人联机功能。

### 浏览器与运行环境

- 建议使用支持 Canvas 2D、Web Audio 和 Pointer Events 的现代浏览器，例如较新的 Edge 或 Chrome。
- 已在本地内置浏览器做过基础操作检查，尚未完成各浏览器与手机真机的全面兼容验证。
- 游戏采用 `640 × 480` 逻辑画面，页面会根据窗口缩放并保持像素风格。
- 运行资源均在本地，不依赖在线字体、CDN 或远程游戏接口。
- 全屏、声音播放和本地记录能否使用，也受浏览器能力及当前设置影响。

## 操作说明

### 键盘

| 动作 | 按键 | 说明 |
| --- | --- | --- |
| 向左移动 | `←` / `A` | 同时改变角色朝向 |
| 向右移动 | `→` / `D` | 同时改变角色朝向 |
| 跳跃 | `Space` / `W` / `↑` | 在空中可再按一次，进行二段跳 |
| 近战攻击 | `J` / `Z` | 可按住连续攻击；攻击期间移动速度降低 |
| 范围魔法 | `K` / `X` | 每次按下释放一次，需要足够魔力 |
| 暂停 / 继续 | `P` / `Esc` | 也可点击游戏上方按钮 |
| 重新开始 | `R` | 从第一组场景重新开始，当前得分清零 |
| 开始 / 确认 | `Enter` | 在开始、暂停、失败或过关界面执行相应操作 |

跳跃和魔法需要再次按下才能再次触发，持续按住不会自动重复释放。近战攻击支持长按。

### 触屏与鼠标按钮

在窄窗口或触屏设备上，游戏下方会显示左右方向、魔法、攻击和跳跃按钮：

- 按住方向按钮移动。
- 按住攻击按钮连续攻击。
- 点击跳跃按钮起跳，在空中再次点击可二段跳。
- 点击魔法按钮释放范围攻击。

顶部“声音”按钮用于开启或关闭声音，“全屏”按钮用于切换游戏画面的全屏状态。目前没有独立音量滑块，需要通过系统或浏览器调整音量。

切换窗口或将页面放到后台时，游戏会自动暂停，避免角色在失去操作时继续移动。

## 玩法与规则

以下数值描述的是**当前网页版规则**，不是从原版 EXE 中确认的原作参数。

### 冒险流程

原版是 16 个独立的单屏战斗场景，分为三组资源，各有 6、5、5 屏。小关清场后自动将镜头水平滑向下一场，约 1.05 秒后恢复操作，同一大关内音乐连续播放。仅第 6、11、16 场完成时显示大关结算。滑动期间暂停战斗，并清除上一场按键，避免误触。滑动速度和缓动曲线是网页版的过场实现，尚未证明与原版逐帧一致。

| 场景范围 | 资源组 / 网页名称 | 关键敌人 |
| --- | --- | --- |
| 1–6 | 第一组 / 翡翠森林 | 哥布林及狼的不同变体，第 6 场为狼人 |
| 7–11 | 第二组 / 幽蓝遗迹 | 骷髅变体、第 11 场双石像怪和两只 kumo 特殊怪 |
| 12–16 | 第三组 / 暮色古城 | 石像怪变体、kumo，第 15 场狼人再战，第 16 场法师 |

每场地图为 640×480 像素。网页版中文区域名称为自行命名；关卡顺序、生成数量及资源绑定来自原程序静态分析。完整名单、地址和局限见 [原版关卡证据](docs/reverse/stage-native.md)。原程序显式区分的重要场景是 6、11、16，并非每个小场景都有独立 Boss。

### 敌人怎样攻击

- 普通近战敌人接近后进入蓄力，头顶出现提示，再出招、收招；不会停在判定范围之外空转。
- 哥布林和骷髅使用近战，狼与狼人会向前扑击。
- kumo 雷云使用原程序的飞行、制动、蓄力和纵向雷击规则；不再发射自创小球或扇形弹幕。
- 最终法师使用原程序的角度展开弹、锁定雷击、追踪弹、分身、瞬移横向攻击、直线加速弹及三个帮手之间的电链。不同动作受血量阶段和难度分支控制，不会将所有招式随意塞入循环。
- 石像怪已移除没有原版依据的远程弹幕，目前保留近战重建规则；完整的原生近战状态机仍待核对。
- 蓄力和收招期间不会造成近战伤害，同一次出招最多命中一次。
- 躲到攻击方向背后、离开范围或拉开高度差可以避开近战；远程弹体可被实体地形挡住。
- 普通怪可被击中打断，Boss 的受伤闪烁不取消已开始的蓄力，避免被连续轻击永久锁住。

强敌低血量时的加速、再战参数、当前 HP 和出招节奏均为网页版重建规则，尚未恢复原版数值。

### 生命、魔力与攻击

| 项目 | 当前规则 |
| --- | --- |
| 生命上限 | 8 格 |
| 魔力上限 | 100 点 |
| 魔力恢复 | 正常游戏中每秒恢复 5 点，暂停时不恢复 |
| 近战伤害 | 每次挥击对同一敌人造成 1 点伤害，不会在同一挥击中重复命中 |
| 魔法消耗 | 每次 35 点 |
| 魔法伤害 | 对范围内敌人造成 3 点伤害，覆盖角色两侧 |
| 普通敌人接触伤害 | 1 格生命 |
| 守卫接触伤害 | 2 格生命 |
| 受伤保护 | 短暂无敌和闪烁，并有击退效果 |
| 进入下一组场景 | 生命与魔力恢复到上限，累计得分保留 |

魔力不足时不会释放魔法。击败敌人或拾取晶石也会恢复少量魔力。当前没有单独的治疗道具系统。

### 坠落与重新开始

坠落扣除 2 格生命；仍有生命时回到当前单屏地图的安全起点附近，保留当前敌人状态和得分。生命耗尽后，可以重新选择起始关卡再出发。

进入下一场时恢复生命和魔力，累计得分保留。`R` 始终从第 1 场重新开始；开始界面的起始关卡选择也可用于直接练习强敌。

刷新、关闭页面都会结束当前进度，目前只持久保存最高分。

### 计分与本地记录

| 行为 | 分数 |
| --- | --- |
| 命中敌人 | 每次命中 +30 |
| 击败普通敌人 | 额外 +150 |
| 击败关底守卫 | 额外 +1200 |
| 拾取晶石 | +80 |
| 清除一场全部敌人 | +1000 |

最高分使用浏览器 `localStorage` 保存，键名为 `mystic-best`。当前场景进度不写入存档，也不兼容安装版 `Savedata`。

不同浏览器、不同端口及直接文件打开方式可能使用不同的存储空间，因此最高分不一定共享。无痕模式、清理网站数据或禁用存储，也可能导致记录丢失；存储不可用时，仍可继续当前游玩。

## 技术实现

### 页面与游戏循环

项目使用原生 JavaScript，无前端框架、打包器或 npm 运行依赖。

- Canvas 2D 负责绘制游戏画面。
- `requestAnimationFrame` 驱动画面刷新，物理和游戏规则采用 `1/120` 秒固定时间步推进；这不意味着显示器每秒一定绘制 120 帧。
- 摄像机跟随角色水平移动，绘制当前单屏地图。
- 背景以较慢速度滚动，形成视差效果。
- 碰撞、音频和主游戏逻辑分别存放在独立文件中。

### 地图与碰撞

单个图块为 `16 × 16` 像素，一屏对应 `40 × 30` 个图块。每 30 行是一屏。基础导出数据仍保留三组图块数组，游戏按照 encounters.js 中的原程序屏号选出对应 40×30 区域，不将它们当作一条连续关卡。

地图数据包含图块层 `tiles`、属性层 `attrs` 和地面偏移 `surfaceOffset`。属性目前按以下语义使用：

| 属性值 | 网页版解释 |
| --- | --- |
| `0` | 空白，不提供地形碰撞 |
| `1` | 实体地形 |
| `2` / `3` | 两种方向的坡面 |
| `33` | 可从下方跳穿、从上方落下站立的单向平台 |

角色物理位置以脚点为基准。可见草地会伸出属性格边界，因此第一组使用 7 像素、第二和第三组使用 3 像素的 `surfaceOffset`，统一校正地面、坡面及碰撞采样。

这些属性语义与偏移是根据资源、画面和测试推导的当前实现，尚未逐项与原 EXE 确认。特殊地形仍可能需要单独校正。

### 声音与输入

MIDI 在提取时被转换为音符起点、时长、音高和力度，运行时由 Web Audio 调度振荡器发声，直接使用原始音符而不是在浏览器中加载 MIDI 播放插件。

键盘和触屏按钮共用同一组动作状态。角色图集方向映射为：`thany_a1` 朝左，`thany_a2` 朝右。

## 重新提取资源

### 环境要求

只有重新生成资源时，才需要：

- Python 3；
- Pillow 图像库；
- 保持上述原版资源与 `web` 的相对目录结构。

如果缺少 Pillow，可在选定的 Python 环境中安装：

```powershell
python -m pip install Pillow
```

### 执行转换

以下命令均在 `web` 目录执行：

```powershell
python tools/extract.py
python tools/extract_native.py
```

脚本根据自身位置寻找上一级原版目录，不会运行 `Mystic.exe`，也不会修改原始 CNX、BRM、MLK 或存档文件。它会重新生成并覆盖 `assets` 中同名的输出文件；如手动修改过这些输出，请先备份。

转换流程包括：

1. 解压 CNX 并校验结果长度。
2. 解析 GMP 的尺寸、调色板及 4/8 位索引像素。
3. 翻转倒序存储的图像行，处理相应资源的透明色并导出 PNG。
4. 解析三组地图的图块层与属性层，检查图块索引范围。
5. 在 MLK 中定位六段 MIDI，导出独立文件并解析音符事件。
6. 写入 `assets/data.js` 和 `assets/manifest.json`。

当前资源的成功输出为：

```text
Validated 47 images; 3 maps; 6 MIDI songs / 12305 notes
```

`extract_native.py` 只依赖 Python 标准库，读取原始 Mystic.exe 中已确认的图集描述表，并使用 docs/reverse/stage-native.json 中的静态关卡记录导出 native-atlas.js 与 encounters.js；不需要 REA 或 Ghidra。

`data.js` 作为普通脚本加载，提供 `window.GAME_DATA`，因此运行时无需请求原始二进制文件。修改导出规则时应修改 `tools/extract.py`；只修改 `assets/data.js` 会在下次提取时被覆盖。

## 测试与验证

### 手机横屏游玩

手机打开页面后使用精简的横屏游戏布局，只显示完整游戏画面、暂停/声音/全屏和触控键。竖握时页面本身旋转90度，将手机横过来即可操作；设备切换为物理横屏后，页面会自动重新适配。画面保持原版4:3，按可用宽高放大，按钮使用两侧空余区域，避免遮住地形。

点击“开始冒险”会尝试进入全屏并锁定横屏；浏览器不支持或拒绝时仍能使用页面横屏布局。iPhone/微信等浏览器能否隐藏系统栏取决于浏览器支持，尚未做实体手机验证。`mobile.js`跟随Visual Viewport变化更新尺寸，`mobile.css`负责安全区和精简布局；桌面保持原页面。运行`node test-mobile.cjs`可检查尺寸与全屏降级逻辑。

若手机出现仅声音/全屏按钮可见的黑屏，请刷新最新版本（mobile3）。新版对所有游戏容器设置明确尺寸，并直接计算画面的像素宽高，避免旋转时嵌套自动高度的兼容风险。若页面仍复用旧HTML，可在当前地址末尾加`?v=mobile3`重新打开。此调整已通过Chromium尺寸检查，原iPhone设备仍需复测，不能将桌面模拟等同于实机结果。

### 特殊怪的原版依据

本轮没有使用 REA 或 Ghidra。根据本地 `Mystic.exe` 的 PE 数据和 Capstone 静态反汇编，分别实现 `native-cloud.js`、`native-mage.js` 和共用的 `native-hazards.js`。雷击、弹体、横向攻击和电链使用原图集帧与已确认的活动窗口。雷击地面查询使用原程序对应的地形规则，与人物脚点的视觉校正分开。

招式地址、时序和限制见 [雷云与石像怪证据](docs/reverse/cloud-golem-moves.md) 和 [最终法师证据](docs/reverse/mage-moves.md)。当前仍有保留项：原生帧率尚未确认（宿主使用 60 tick/s）、定点数截断和全局漂浮偏差未逐帧对齐、原生伤害类型与受击打断未完整移植，HP/伤害沿用网页缩放。因此这不是已证明完全等价的原版 Boss；未确认的内容不另编技能代替。

特殊怪模块的独立测试：

```powershell
node test-native-cloud.cjs
node test-native-mage.cjs
node test-native-hazards.cjs
```

这些测试核对雷击次数与活动窗口、法师招式分支与弹数、分身独立计时、瞬移位置、电链判定和固定 tick 更新，以及小关自动切换、大关结算与过场暂停。它们验证已转写的规则，不等于人工完整通关或逐帧对照原版录像。

### 自动化检查

需要安装 Node.js。在 `web` 目录执行：

```powershell
node --check game.js
node --check audio.js
node --check physics.js
node --check enemy-ai.js
node test-enemy.cjs
node test-physics.cjs
node test-game.cjs
```

不需要先运行 `npm install`，测试使用 Node.js 内置模块。

目前覆盖：

- 实体地形落地、两个方向的坡面；
- 单向平台向上穿过与向下落地；
- 地面偏移及长时间站立稳定性；
- 角色出生、移动、二段跳；
- 同一次挥击对同一敌人的伤害去重；
- 魔法伤害和魔力消耗；
- 暂停时停止人物物理更新；
- 16 场清场状态、敌人数量、关键强敌身份和场景切换；
- 普通怪从接近到命中人物、蓄力/收招无伤害、单次出招去重、躲避、硬直和死亡中断、法师弹体触发；
- 失败和重新开始；
- 左右输入对应的站立、行走、跳跃和攻击图集；
- 三组原始地图的平台上，各连续攻击 20 秒不发生脚点下沉。

游戏逻辑测试在模拟 DOM、绘图及音频环境中运行。清场测试设置了“全部敌人已被击败”等前置状态，用来检查流程逻辑；它不等于实际操作通关。测试也不能替代画面、音效和真实手感检查。

### 建议手动检查

改动动作、动画或地形后，至少检查以下场景：

1. 分别按左、右方向，观察朝向和移动是否一致。
2. 在平地、坡面和单向平台上站立、走动、攻击。
3. 从平台下方跳穿，再落回平台顶部。
4. 连续攻击，观察脚部是否稳定以及命中方向是否正确。
5. 跳跃中使用攻击和魔法，观察空中状态。
6. 受伤、坠落返回和死亡重开。
7. 暂停、恢复以及切换窗口后的状态。
8. 在窄窗口中检查触屏按钮是否可见并可操作。

历史检查详情见 [验证记录](docs/验证记录.md)，问题修复情况见 [问题与解决记录](docs/问题与解决记录.md)。

## 常见问题

### 页面一直显示“正在读取原版资源”或“资源加载失败”

先确认没有只打开单独复制出来的 HTML 文件，`assets` 和运行脚本应与入口文件保持原目录结构。刷新页面后重试；必要时改用本地 HTTP 服务，检查浏览器控制台和网络面板中失败的文件名。

当前图片采用每批五张加载，单张失败最多重试两次。若文件缺失或损坏，再运行资源提取脚本；不要仅通过重复刷新掩盖具体错误。

### 打开后没有声音

先点击“开始冒险”，再检查顶部声音开关、浏览器标签页静音状态和系统音量。浏览器通常需要用户点击后才允许启动音频。

当前声音是原 MIDI 音符的简易合成版本，音色和部分声部与原作不同属于已知限制。

### 按键没有反应或网页在滚动

先点击游戏画面，让浏览器页面获得输入焦点；确认没有停留在地址栏、其他窗口或开发者工具中。如果游戏已自动暂停，点击“继续冒险”或按 `P`。

### 更新代码后仍然看到旧效果

刷新页面；如果使用本地 HTTP 服务，可以尝试 `Ctrl+F5` 强制刷新，并确认当前页面使用的端口和目录正是正在修改的版本。

刷新会结束当前游戏进度。

### 为什么全屏不可用？

全屏依赖浏览器及宿主环境支持，部分内嵌页面会限制它。可改用浏览器自身提供的全屏方式，或放大窗口游玩。

### 为什么最高分消失，或者文件版与服务版的最高分不同？

记录只属于当前浏览器的当前存储空间。更换浏览器、端口、打开方式，或清理浏览器数据，都可能看到不同记录。本项目没有云同步。

### 人物仍有朝向、穿地或动画错位

先刷新确认加载了最新脚本。如果仍可复现，请记录当前场景、区域编号、所在平台、使用按键，以及是否刚受伤或落地，最好附截图或短视频。

目前已修复左右图集反向，并校正了常规地形的可见顶面偏差。但这不代表所有特殊地形、动画组合和受击状态都已验证完毕。

### 能否只复制 web 文件夹到别的电脑？

已有转换资源时可以，需保留完整运行目录。Windows 启动脚本仅适用于 Windows；其他系统可直接用浏览器打开 `index.html`，或使用当地的静态 HTTP 服务。

重新提取资源则仍需原始 `Cnx`、`Dat`、`Mystic.exe` 及对应目录关系。项目目前没有自动发布、托管或打包脚本。
