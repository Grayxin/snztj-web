# 雷云与石像怪：原始程序招式证据

本记录读取随游戏提供的 `Mystic.exe`、现有 `Mystic.asm` 和已提取的原图。仅使用本机 Python 的 PE/字节读取和汇编分析，没有使用 REA、Ghidra，也没有安装工具。地址均为该 EXE 的虚拟地址。未证明的部分明确列出，不用猜测补成原版招式。

## 雷云（kumo）

构造函数 `0x4550f1`，更新函数 `0x4553b0`。这是飞行怪，真正的攻击是落雷和蓄力后段的局部身体碰撞，不是追踪球、扇形球或任意环形弹幕。

### 坐标、强度与移动

- 原始坐标采用 16.16 定点数；对象坐标是 48×48 精灵的左上逻辑原点。`+0x1d4`、`+0x1d8` 均为 24 像素（`0x45538f`）。网页用水平中心、脚底坐标，所以 nativeX=`e.x−24`，nativeY=`e.y−48`；雷电中心 x=nativeX+24=`e.x`。
- 构造强度 P=`min(构造参数,127)+(global[0x51b368]<<6)`，见 `0x4550f7`、`0x4552e7`。网页适配器用 `nativePower + w.difficulty`，其中普通难度偏移当前为 64；可用 `nativeProfile` 直接给总值。原始全局的具体 UI 难度名称尚未追溯。
- 随机相位初值 16，每 tick `(phase+101)&65535`，再折叠至 0..32768（`0x4553f9`）；这是飞行选点的确定性序列，不是每帧重新随机。
- 每 120 tick 重选目标（`0x455fed..0x456147`）。玩家原点 y>192 时，目标 x 为玩家中心 x 加 `(r&255)−128`，左右越界时反向偏移；目标 y 为玩家原点 y−128 加 `(r&63)−32`。玩家原点 y<=192 时，目标 x 基准为玩家在左半屏则480、否则160，再加上述偏移；目标 y=`64+r%80−40`。
- `0x45614d..0x456340` 依据目标方向加速（方向分量 /16），再按 `(方向分量+摆动分量/2)/2` 对速度分量做符号对应的单侧限制。位置每 tick 加速度值（`0x457439`），没有重力/地形行走。视觉上下摆动为 `3*sin(65535−phase)`（`0x45640d`）；视觉相位每 tick+150。
- `native-cloud.js` 内嵌原始正弦表 `0x4958a0`、反正切表 `0x4960a4`，按 `0x4134b0`、`0x413593`、`0x413668`、`0x4136f4` 复现方向、量化和定点计算，不用自创悬浮追踪速度。

### 攻击触发与时序

`0x4565c9..0x4566d2` 检测玩家身体与竖条相交：nativeX+8 到 nativeX+40，屏幕 y=0..480。`0x403c8e` 实际读取玩家身体矩形，而不是仅比较玩家中心。

对齐计时 `+0xec` 为空时设为 `30−2*(P>>5)`；公共计时和对齐分支各递减一次。对齐计时变为1且冷却 `+0xe4` 为0时，进入攻击状态1或2，并将冷却设为 `2*(64−(P>>3))`。离开竖条则清空对齐计时。

状态选择比较 `+0x1b4 > (256−P)*2+300`，满足进入2，否则1；`+0x1b4` 每 tick 递减，受击处理中的部分路径会累加。该字段不能随意改成“血量低于一半狂暴”。受击分派 `0x45568e..0x4556d9` 读取 `(+0x214 &0x7f00)>>8` 的原始攻击类型，并通过 `0x457770/0x457798` 跳转。已经直接解出类型→压力累加：1/8→60，2→240，3→180，4→120，5→160，6/10→300，7→0，11/96→30，80→50。`MysticCloud.onHit(e,{nativeAttackType})` 提供此精确映射；未知类型返回false，不猜测换算。网页原有普通伤害/魔法类别与这些原始枚举的对应尚未追溯，不应直接把伤害数字当枚举传入。

追加追踪：原生玩家构造 `0x45f7d8` 指向更新 `0x45fa32`；玩家招式状态1经 `0x464614/0x464678` 跳至 `0x463c74`，选择动画动作2。动作2在 `0x4d2550+2*128` 的帧为3/2、15/2、16/10；攻击类型表 `0x4d9d50+2*128` 为0、0、4。因此原始第一段普通攻击的有效帧16是类型4，对雷云累加120压力。网页基础攻击可明确映射到这一段，不能声称整个原版连招已还原。原生招式状态2/3/4/5分别选动作3/4/5/6，对应类型4/6/8/8；网页当前魔法的原生类别仍未知。

状态1、2进入后计时54 tick，播放原始声音索引30；水平速度乘95%，垂直速度乘98%（`0x456b26`、`0x456c15`）。以下均为**剩余计时**，由大到小执行：

| 状态/强度 | 生成落雷的计时与相对中心偏移 |
|---|---|
| 状态1，任意 P | 6：0 |
| 状态2，P<=64 | 6：0 |
| 状态2，64<P<=128 | 12：+12；6：−12 |
| 状态2，P>128 | 16：−12；12：+12；8：0 |

所有分支调用 `0x423a4a`，并设落雷 vx=`random(511)*512−131072`（定点，即约−2..+2像素/tick）。计时为0返回待机。不是主动根据玩家当前 x 放置落雷。

### 落雷原图、寿命与判定

落雷构造 `0x423a4a`，更新 `0x423cf6`。x 是雷云中心（加招式偏移）。y=`terrainHeight(x)−480`，高度480；查地形函数 `0x401f1e` 在 y=0..479 查找地形类型8，没有找到返回480。因此落雷不是从云的脚底向下延伸的自定义线段。

更新计数达到8删除（`0x423fa9`）。每 tick x+=vx，vx*=95%（`0x423f74`）。图集是 `effect1.png`，精灵槽0x38。帧表 `0x49a008`，每项6个 int32、24字节：`x1,y1,x2,y2,pivotX,pivotY`。

| 原始帧号 | 原图裁剪 xyxy | 轴点 | 持续 tick |
|---|---|---|---|
| 75 | 480,0,528,480 | 24,0 | 2 |
| 76 | 528,0,576,480 | 24,0 | 2 |
| 83 | 464,152,472,160 | 4,4 | 2 |
| 77 | 576,0,624,480 | 24,0 | 2 |

动画表 `0x499448` 随后还有75/2，再以0xfffe/0回到开头；8 tick删除使其不会正常完整循环。构造时0x380034是初始化占位帧52（384,80,416,112,0,0），不能拿它当落雷的实际动画。通用动画器 `0x4019a0` 每帧持续指定 tick，并把当前索引返回给判定表。

判定描述符 `0x4993e8` 的受击框全0，攻击框为相对落雷原点 `(-4,0,16,480)`（x,y,w,h）。`0x499588` 攻击标志表与 `0x4996c8` 攻击类型表均只有动画索引1非零：只有第二个动画条目、即原图帧76的两 tick 是有效伤害窗口。48像素图宽不等于16像素攻击宽，不应整段动画都造成伤害。

### 云本体动画与身体攻击

待机表 `0x4cea20`：帧0/6、1/6、2/6，循环。蓄力表 `0x4ceb20`：`3/2,0/4,4/2,1/4,5/2,2/4` 重复两组，再 `3/2,4/2,5/2` 重复三组，循环。受伤表 `0x4cec20` 使用帧6。

`0x4cf720` 标志表、`0x4cf320` 身体描述符映射、`0x4cf920` 攻击类型表在蓄力后段的奇数动画索引为1；实际可到达的有效索引是13、15、17、19（索引21本身是动画循环标记）。描述符0与1位于 `0x4ce990`、`0x4ce9c0`：身体框都为 `(8,8,32,32)`，仅描述符1的攻击框也是 `(8,8,32,32)`。网页攻击框因此是 `x=e.x−16,y=e.y−40,w=32,h=32`；待机时没有身体攻击窗口。

### 移植接口与剩余范围

`MysticCloud.create(e)` 初始化，`step(e,w,dt)` 以60Hz默认固定步长推进，并完全更新e.x/e.y。原始启动等待99、完整受击状态64/65、死亡演出和公共引擎的外部推力没有在该模块中搬运；上层继续处理生命值/受伤闪烁/死亡。没有将这些未移植部分替换成新招式。

`w.player` 提供 x、y（中心/脚底），可提供 nativeX/nativeY、centerX；默认原生玩家原点按 x−24/y−64适配。`w.playerRect` 应提供网页已有的实际身体框；默认24×48仅是网页框适配，不声称来自原始玩家碰撞表。`w.emit(e,event)` 接收 kind=lightning 事件与原始寿命、动画、攻击框；上层按场景地形求 y。`e.nativeFrame` 为原始kumo图集帧号，`nativeVisualOffsetY` 仅用于绘制，`nativeContact`/`nativeContactRect` 为当前身体攻击窗口。

## 特殊石像怪（关卡11的 gor2 / gor3）

分析更新函数 `0x44fb0b`、`0x452345`。这两个函数没有证明存在瞄准球、扇形飞弹。之前若给它们加了这些招式，应删除，不能把死亡碎石误作攻击。

gor3的状态分派 `0x453a0a`（表 `0x454c05`/`0x454c2d`）映射：1→453a11，2→453aa7，3→453b3d，4→453bd3，64→453caa，65→453d08，100→453e10。主动招式1/2/3/4计时分别52/54/86/104 tick，初始vx来自朝向/输入，之后在未硬直时vx*=90%，计时结束回0。这是原始近战状态序列的证据，完整每帧攻击框仍需继续搬运，不能称当前网页普通近战已逐招还原。

状态1触发在 `0x4534d6`：前方距离>=4且<64、冷却为0，冷却=`((256−P)>>5)*8+45`。状态4触发 `0x453580..0x453667`：前后距离探测都为−1，玩家与向前取半幅并向下延伸80的区域相交，且冷却为0；冷却=`trunc((256−P)/3)+120`。状态2、3的完整触发/伤害帧此次未完整落实，保留待核实。

状态100是死亡（由生命值分支 `0x45105c`/`0x4539b2` 进入）。死亡计时100，剩余99生成 `0x4229fb` 扩张特效；98隐藏本体并调用 `0x454d42` 生成三块碎石（帧26、27、28，延迟0/10/20）；95调用 `0x42249e` 视觉特效；80再调用 `0x4229fb`。`0x454d42`/`0x454e8f` 碎石是零伤害判定的死亡碎片，随机初速、寿命60、重力+0x3000、vx*=95%，后30tick闪烁。上述视觉效果不能移植为战斗中的远程弹幕。

## 验证

`node web/test-native-cloud.cjs` 覆盖原始朝向象限、固定步长一致性、竖条对齐触发、单/双/三落雷的偏移与顺序、原始帧和窄攻击框、云本体后段攻击窗口。静态地址和表直接来自随游戏文件；没有把单元测试结果当作与原版逐帧运行对照的替代。
