# 《圣女之条件》安装版网页化初步分析

日期：2026-10-23。范围：静态检查本地文件，未启动游戏，未修改原始程序及资源，未安装 REA。

## 已确认

- 主程序 Mystic.exe，925696 字节，PE machine 0x14c（32 位 x86），包含 Mystic Arts 字符串。
- 导入 DirectDrawCreate（DDRAW.dll）、DirectInputCreateA（DINPUT.dll）以及 DSOUND.dll、WINMM.dll；属于原生 Windows/DirectX 程序。
- 原始目录共 62 个文件，4722876 字节，包含卸载器。
- Cnx 下有 47 个 CNX 图片资源；文件头 CNX 02 GMP，47 个文件均满足偏移 8 的大端 32 位整数等于文件长度减 16。偏移 12 的字段疑似解压后长度，尚未验证；未成功解码图片。
- Dat 下六个 BRM 文件，签名 BRUN100。偏移 8、10 的小端 uint16 与剩余数据按 uint16 网格计算完全匹配：STGa01/STGf01 为 40×180，另四个为 40×150。f 组值最大 279；a 组仅 3–5 种值、最大 33。推测分别是图块层和属性层，具体语义待验证，不能据此保证只有三个游戏关卡。
- MysticA.mlk 内找到六处 MIDI MThd 头，位置 55、24248、47860、50349、85395、111369。文件开始的索引与这些位置相符；音乐提取很有希望，但未进行播放验证。
- MysticA.wlk 签名 WLKF0200，可能是音效容器，尚未解码。
- Savedata/Mystic0.dat 仅 20 字节，尚未确认字段含义。
- EXE 包含角色/敌人/界面资源名以及关卡资源文件名模板；游戏规则与状态机预计需要从 EXE 或实际运行行为恢复。

## 可行性与方案

1. 推荐：资源转换 + 浏览器原生重实现。先验证 CNX 解码、关卡网格与角色动作，再使用 Canvas/WebGL 实现游戏循环、输入、碰撞和敌人状态。优势是页面加载轻、适配键盘及触屏；难点是还原手感与完整流程。
2. 浏览器中模拟 Windows 环境运行 EXE。可能保留原始逻辑，但 DirectDraw/DirectSound 兼容性与性能未验证，不能认为把 EXE 放进网页就能运行。
3. 从零制作玩法类似的版本。可较快实现可玩内容，但对还原原作的帮助较小。

建议首个里程碑：解出标题图、主角图集与一张地图；实现一小段可移动、跳跃、攻击、受伤的场景，与原作运行结果对照。通过后再扩大到完整内容。

## REA 判断

REA 是连接分析工具的 CLI/MCP，不是 EXE 到 HTML 的转换器。初步资源检查不需要安装它。若目标是尽量忠实还原，深入恢复 EXE 中的角色状态机、碰撞规则和关卡触发时会有帮助。

官方当前说明：Windows 可接已有 IDA，或使用实验性 Ghidra 支持。Ghidra 路线要求已有 Ghidra 12.1.x 和 64 位 JDK 21+；REA 还需要受支持的 Node.js。仅安装 REA 不足以完成原生反编译。

## 2026-10-23 网页版实施更新

后续已验证：47 个 CNX 均成功解压，GMP 为倒序行存储的 4/8 位索引色图片，已转为 PNG。三组 BRM 按每 30 行组成一屏，转为横向 6/5/5 屏关卡。MLK 六段 MIDI 已导出并解析为音符事件。属性 1 作为实体、33 作为单向平台、2/3 作为坡面用于重建碰撞；这些语义与图像对照后合理，但未对原 EXE 逐条验证。

可运行版本、操作及还原边界见 README.md。当前无需 REA 即可运行；忠实还原原始状态机、敌人 AI 和 WLK 音效仍需后续分析。

## 2026-10-26 · 原版关卡与敌人行为修正

以此节及 reverse/stage-native.md 为准：原版是 16 个独立 640×480 场景，三组 BRM 分别包含 6、5、5 场。旧版“横向长地图、每组一个骷髅守卫、传送门出口”是早期重建选择，已撤换。

通过普通静态 PE / 反汇编分析，已核对全部生成名单、资源族绑定、清场计数器、关键强敌场景，以及大型敌人的矩形帧表。未使用 REA/Ghidra 分析程序。原版场景 6 是狼人，11 是特殊双石像怪和 kumo 组合，15 是狼人变体再战，16 是法师。详见 reverse/stage-native.json。

网页当前使用原版名单、图集和场景顺序；敌人 AI、HP、出招窗口、弹体速度和部分表现仍是重建实现，不应称为完整逆向复刻。
